# 本地赛道计次裁决台

一个完全本地运行的赛道计次（lap counting）裁决工具：录入 1～3 名选手、两段合格耗时区间与至多 40 条感应记录，自动为每名选手选出最优的完整计次方案；并可把**设备导出的感应日志（UTF-8 CSV）经 HTTP 预览后并入当前记录表**；还可在结果区对未采纳记录发起 HTTP“替代性诊断”，逐条判定同优可替代 / 仅次优可用 / 无法成趟；另提供**“查找漏读”**：推测只补一条读数就能多完成一趟的时间窗。对暂时存疑的感应记录，可在页面每行**隔离/重新纳入**，原始读数保留在表中、计算只用未隔离记录（裁决、诊断、漏读均支持可选 `excludedIds`）。复核全部“通过”后，可把当前裁决**发布为独立的只读成绩公告**：服务端重新裁决并核对复核与罚秒、按原规则生成名次，按编号版本化保存进 SQLite（Compose 数据卷跨重启保留），经 HTTP 按编号与可选版本读取。已发布公告的**完整版本链可经 HTTP 导出为 JSON 归档并导入另一实例**完成迁移——不重新裁决、不覆盖当地历史（详见“公告迁移”节）。

- 后端：Python + FastAPI（`app/`），成绩公告用 SQLite 持久化（`app/bulletin.py`）
- 前端：原生 HTML / CSS / JavaScript，无构建步骤（`static/`）
- 裁决算法：枚举合法趟 + DAG 动态规划（`bisect` 二分前驱），含 400 组随机数据对拍测试
- 诊断算法：在同一合法趟 DAG 上做前缀/后缀最优 DP，求“包含指定趟”的最优完整链；另含 500 组随机数据与暴力 DFS 的对拍
- 漏读算法：只比趟数的前缀/后缀 DP + 单调性二分求区间端点（不逐秒扫描），含 400 组随机数据与逐秒暴力参考实现的对拍

## 裁决规则

每趟从同一选手的感应记录中依次选取 **起点 S → 中途门 M → 终点 F** 各一条：

1. 两段耗时（M−S、F−M）都必须落在录入的**正整数闭区间**内；
2. 同一选手的不同趟**不得共用任何记录**；
3. 后一趟的起点秒数必须**严格晚于**前一趟的终点秒数（`后起点 > 前终点`）；
4. 其余读数一律舍弃，列入“未采纳记录”。

记录可以乱序录入，同一秒允许存在多条记录。

### 记录秒数（任意大的非负整数）与页面精度

- 记录秒数是**非负整数，位数不限**：允许超过 JavaScript 安全整数范围（2^53）的秒数，如起点 `9007199254740992`、中途门 `9007199254741003`、终点 `9007199254741014`，取值范围不会因页面而缩小；
- 后端按任意精度整数接收秒数（JSON 整数或十进制字符串均可）并精确计算两段耗时；前端从响应解析、页面展示、两段差值计算、名次表用时而到**人工复核绑定**，秒数及其差值全程以**规范十进制字符串**保存与比较（差值用 `BigInt` 计算，不经过 `Number`），不发生任何浮点截断；前导零等值写法（如 `"0011"` 与 `"11"`）归一；
- 因此，即使两条记录秒数相差极小、且秒数本身已超过 2^53（例如两段各 11 秒：…40992 → …41003 → …41014），页面显示的两段耗时仍是精确的 **11 / 11 秒**，不会被算成 12 / 10。

> 复现（修复前）：两段区间均填 10～60 秒，选手 101 录入 S/M/F 三条记录，秒数依次为 `9007199254740992`、`9007199254741003`、`9007199254741014`，裁决得到一趟、两段各 11 秒。给该趟保存“通过”和备注后，**添加一条空记录行**（或重排记录行）触发重算：旧实现把秒数经 `Number` 截断（中途门被截成 `9007199254741004`），两段差值在复核绑定核对中变成 12、10，于是绑定被误判失效，状态变回**未复核、备注消失**，页面展示的秒数也被改写。修复后：秒数与两段差值在响应处理、页面展示和复核绑定判断中始终精确；绑定未变且仍采纳的趟，重排记录、增删无关记录（含空行）与手动重算都保留复核。

### 选手编号约定（任意大的正整数）

- 编号是**正整数，位数不限**：允许超过 JavaScript 安全整数范围（2^53）的大编号，如 `9007199254740992` 与 `9007199254740993`；
- 编号从输入、API 请求/响应到结果展示、罚秒归属、名次表编号排序、人工复核绑定**全程无损**：前端以十进制字符串原样发送与解析（不经过 `Number` 截断），后端按任意精度整数处理，两个相差 1 的大编号不会被混同；
- **前导零等值写法视为同一编号**：`007` 与 `7`、`09007199254740992` 与 `9007199254740992` 是同一个编号，改写写法**不算改号**，不会触发罚秒释放或复核失效；
- 不同编号的罚秒与复核**互不影响**；真正改号或删行时原编号罚秒立即释放、复核按原绑定规则立即失效（输入非法、防抖合并、请求在途都不会延迟失效），改回不恢复。

> 复现（修复前）：录入选手 `9007199254740992` 与 `9007199254740993` 并裁决，两人编号曾显示相同，给前者保存 7 秒与原因会同时影响后者；仅有前者时把编号改成后者，旧处罚也不会立即清除。修复后以上场景均按两个不同编号正确处理。

每名选手按以下优先级选择方案：

1. **完整计次数最多**；
2. 计次数相同时，**各趟用时之和最短**（每趟用时 = 终点秒数 − 起点秒数）；
3. 仍相同时，取按计次时间顺序串接的记录 ID 序列**字典序最小**者。

没有任何完整一趟时显示 **0 次**；输入非法时只报错、**不展示任何部分结果**。修改任意输入（耗时区间、选手、感应记录，含增删行与载入示例）后，页面会按当前完整输入**自动重算所有选手**，无需再点按钮；连续编辑会合并为一次重算，“⚖ 裁决 / 重新计算”按钮仍可随时手动触发。输入非法时只显示错误，改回合法值后自动恢复裁决；等待响应期间可继续编辑，只有仍适用于当前输入的响应才会更新结果或错误。

## 可疑记录隔离（暂时退出计算，原始读数保留）

对暂时存疑的感应记录，可点记录行内的**“隔离”**按钮让它暂时退出计算，再点同一行的**“重新纳入”**恢复：

- **原始读数不删除**：被隔离的记录始终留在记录表中，可继续查看与编辑；仅裁决、替代性诊断与漏读的**计算**跳过它们。
- **切换后自动裁决**：每次隔离/纳入都与修改输入同生命周期——立即清除旧结果、旧诊断、漏读窗口与导入预览，随后防抖自动重裁；切换前在途请求的迟到成功或失败（含断网）都被版本守卫丢弃，不回写界面。
- **结果分列**：每名选手的结果中，被隔离记录单列在**“隔离记录”**小节，与普通**“未采纳记录”**分开；隔离记录既不会被采纳，也不算作未采纳。某选手的记录被全部隔离时按 **0 次**处理。
- **隔离绑定到具体记录**：绑定 **ID、选手编号、门、秒数** 四元组，按现有规则比较——ID 去首尾空白，选手编号与秒数按整数等值（前导零写法如 `0101` 与 `101`、`012` 与 `12` 视为相同，不算改变），门按字符串精确比较，任意大的编号/秒数全程精确。**任一绑定值改变或该记录被删除（含同 ID 出现多行无法唯一定位），隔离立即解除；之后改回原值或补回同 ID 记录都不恢复。**
- **重排与无关编辑保留隔离**：拖动/移动记录行、增删改其他记录、编辑区间或不影响绑定的写法变化（前导零）都不解除隔离；**“清空”、“填入示例”与刷新页面**清除全部隔离（仅页面内存，不写 localStorage）。
- **隔离不影响其他会话状态**：不释放任何选手的罚秒；人工复核沿用原绑定规则——趟因隔离不再被采纳时其复核按原规则清除，重新纳入后若该趟再次被采纳，旧复核**不恢复**。
- **设备日志合并不受隔离影响**：合并仍对**完整原表**做去重、冲突检测与计数——被隔离的 ID 与文件内容冲突仍整批拒绝，隔离记录仍占用 40 条名额，隔离不能跳过冲突或绕过限额；导入 context 不携带 `excludedIds`。
- 三个计算端点（`/api/adjudicate`、`/api/diagnose`、`/api/missing`）都接收可选的 `excludedIds` 数组：**缺省或为空数组时行为与不传完全一致**；数组元素必须是去空白后**不重复的现有记录 ID**，否则返回 `422`。完整输入与 40 条限额仍先按原规则校验，非法输入不会因为隔离而变合法。

## 成绩公告（只读发布，SQLite 持久化，版本化读取）

页面底部的**“成绩公告”**卡可把通过复核的裁决发布为独立的只读公告：填写**非空公告编号**后点击 **📣 发布成绩公告**，页面以**点击时的快照**提交——完整裁决输入（含隔离 `excludedIds`）、已保存复核、已保存罚秒与**所见公告版本**（该编号首次发布为 0）。

- **服务端重新裁决，不信任页面缓存**：对提交的完整输入按原规则重新计算采纳方案，并逐条核对复核——按**选手 + 三条记录的 ID/门/秒数**匹配到被采纳的趟（两段区间由重新裁决保证）；**每趟均须“通过”**（状态为未复核/存疑、缺少某趟复核、复核与采纳趟不匹配都整次拒绝），**零次选手无需复核**；
- **备注、罚秒及原因沿用原校验**：备注/原因至多 200 字、罚秒非负整数、罚秒大于 0 时原因必填；**未知选手处罚**整次拒绝；
- **名次按原规则在服务端生成**：计次数降序、调整后用时（原总用时 + 罚秒）升序、并列共享名次跳号、零次者末尾无名次；
- **版本匹配才保存**：所见版本与当前最新版本一致时，把输入、采纳方案、复核、处罚及名次一起保存为下一版本并返回公告链接；**同版本并发发布只有一项成功**，过期返回 `409`（响应含 `currentVersion`，页面据此更新所见版本后可再次发布）；**任何失败都不留版本、也不改动现有公告**；
- **公告永久只读**：按编号与可选版本经 HTTP 读取，缺省读最新，未知编号/版本返回 `404`；后续编辑、清空和刷新页面都不影响已发布的公告；发布响应只落在公告卡内，**不改写编辑区**；
- **跨重启保留**：公告存于 SQLite（默认 `data/bulletins.db`，可用环境变量 `BULLETIN_DB_PATH` 覆盖；Compose 部署时写入命名数据卷 `bulletin-data`）；
- **精确性**：公告编号按原样文本保存（任意长的数字串不截断），记录秒数与用时按任意精度整数处理。

公告卡独立于裁决生命周期：不随输入变化清除，也不要求当前存在合法结果——所有校验都在服务端按快照独立完成。

## 公告迁移（双实例导出 / 导入，不重新裁决）

已发布公告的**完整版本链**可经 HTTP 从一台实例迁往另一台实例：导出端把所选编号打成**格式版本 1** 的 JSON 归档（含每版编号、版本、发布时间与完整快照，**整包取自同一数据库时点**），导入端校验后**只追加本地缺失的后缀版本**——**不重新裁决、不覆盖当地历史**。迁移后目标实例的原读取接口照常读最新与旧版，后续发布从最新版本继续；编号、秒数与用时全程精确，发布校验与编辑区不受影响。

### 双实例迁移示例

同一镜像起两个容器（各自独立数据卷，源 8000 / 目标 8001）：

```bash
docker build -t lap-judge .
docker run -d --name judge-src -p 8000:8000 -v bulletin-src:/data \
  -e BULLETIN_DB_PATH=/data/bulletins.db lap-judge
docker run -d --name judge-dst -p 8001:8000 -v bulletin-dst:/data \
  -e BULLETIN_DB_PATH=/data/bulletins.db lap-judge
```

从源实例导出所选编号，并导入目标实例：

```bash
# 1. 从源实例导出（响应的 result 即归档文件）
curl -s -X POST http://localhost:8000/api/bulletins/export \
  -H 'Content-Type: application/json' \
  -d '{"numbers": ["2026-001", "2026-002"]}' \
  | python3 -c 'import json,sys; json.dump(json.load(sys.stdin)["result"], sys.stdout, ensure_ascii=False)' \
  > archive.json

# 2. 导入目标实例（可重复执行：相同版本跳过，只追加缺失后缀）
curl -s -X POST http://localhost:8001/api/bulletins/import \
  -H 'Content-Type: application/json' \
  -d @archive.json
# => {"ok":true,"result":{"added":3,"skipped":0}}
```

源实例后续又发布新版本后，重新导出并再次导入即可增量追上（已迁入版本全部跳过，`added` 只计新追加的后缀）；目标实例本地链更长时全部跳过、本地保留。

### 冲突与非法调用示例

```bash
# 分叉：目标实例同一编号同一版本的快照或发布时间不同 → 409，整批不写入任何编号
$ curl -s -X POST http://localhost:8001/api/bulletins/import -H 'Content-Type: application/json' -d @archive.json
{"ok":false,"error":"公告 2026-001 的版本 2 与本地已发布内容分叉，本次未导入任何编号"}

# 格式非法：格式版本不是 1、版本不从 1 起连续/重复、快照结构不符等 → 422，整批不写入
{"ok":false,"error":"公告 2026-001 的版本必须从 1 起连续"}

# 导出含未知编号 → 整次 404，不生成部分归档
$ curl -s -X POST http://localhost:8000/api/bulletins/export -H 'Content-Type: application/json' -d '{"numbers":["2026-001","ghost"]}'
{"ok":false,"error":"公告不存在：ghost"}
```

详细合同见“API”节的 `POST /api/bulletins/export` 与 `POST /api/bulletins/import`。

## 页面用法

1. 填写两段合格耗时闭区间（正整数秒）；
2. 添加 1～3 名选手，编号必须互异；
3. 录入感应记录：唯一字符串 ID、选手编号、门（S/M/F）、非负整数秒数；全空行会自动忽略，部分填写视为非法；每行有**“隔离 / 重新纳入”**按钮（仅完整行可点），可让可疑记录暂时退出计算而不删除原始读数，详见“可疑记录隔离”节。
4. **无需点击按钮**：修改任意输入（区间、选手、记录，增删行、“填入示例”）后，页面会立即清除旧结果并按当前完整输入自动重算所有选手，结果按选手分卡展示每趟采纳的三条记录与两段/总用时，以及该选手所有未采纳记录。连续编辑会合并为一次重算；输入非法时只显示错误，改回合法值后自动恢复结果。“⚖ 裁决 / 重新计算”按钮仍可随时手动立即重算。
5. “填入示例”可快速载入一份包含多趟、乱序、舍弃读数的数据（载入后自动重算）；“清空”会同时清除输入、结果与错误，此前发出的请求随后返回也不会恢复它们。
6. 合法结果顶部展示**比赛名次表**，可在名次表下方为每名选手保存罚秒与原因，保存后名次立即重排，无需重新裁决；详见下节。
7. 结果区底部提供**“🔎 检查替代性”**：以当前完整裁决输入经 HTTP 诊断各选手的**未采纳记录**（详见“替代性诊断”节）。每次重算（含输入未变的手动重算）都会清除旧诊断并暂时禁止检查，最新合法结果出来后方可重新检查。
8. 诊断卡下方提供**“🧭 查找漏读”**：以当前完整裁决输入经 HTTP 推测“只补一条读数就能多完成一趟”的时间窗（详见“查找漏读”节）。与诊断同款生命周期：输入一改或重新计算即清除，最新合法结果出来后方可重新查询。
9. 页面底部的**“成绩公告”**卡可发布只读公告：填写非空公告编号后点击**“📣 发布成绩公告”**，以点击时的完整输入、隔离、已保存复核与罚秒快照经 HTTP 发布；服务端重新裁决并逐趟核对复核（每趟均须“通过”，零次无需复核），版本匹配才保存并返回公告链接（详见“成绩公告”节）。公告卡独立于裁决生命周期，发布响应不改写编辑区。

## 设备日志导入（UTF-8 CSV，HTTP 预览 → 确认后才追加）

在“4. 从设备日志导入”区选择设备导出的 CSV 文件并点击**预览合并**：页面以 `multipart/form-data` 经 HTTP 上传，服务端按下列规则解析并返回**新增**与**重复（跳过）**条目；确认无误后点击**确认追加**，页面再次经 HTTP 复核，通过后才把新记录追加到记录表并**自动裁决**。

### CSV 格式

- **UTF-8 编码**（允许开头 BOM），表头必须恰好为 `id,runner,gate,time`；支持 RFC 4180 风格**引号字段**：字段可用双引号包裹，字段内可含逗号与换行，`""` 表示一个双引号（如 `"f""1"` 表示 ID `f"1`、`"x,1"` 表示 ID `x,1`）；
- 每行一条记录：`id` 为字符串（沿用现有规则**去首尾空白**），`runner` 为已登记选手的正整数编号，`gate` 为 `S / M / F`，`time` 为非负整数秒；**选手编号与秒数按精确整数比较**，前导零等值写法（`007` 与 `7`、`011` 与 `11`）视为相同，超过 2^53 的编号/秒数在前后端均按任意精度整数处理、不丢精度。

### 去重、冲突与整批拒绝

- **同 ID 且内容一致 → 重复，跳过**：无论该 ID 是与现有记录一致、还是在文件内再次出现（内容一致），都不追加，预览中列入“跳过的重复条目”；
- **同 ID 内容冲突 → 整批拒绝**：同 ID 的选手编号、门或秒数任一不一致（与现有记录冲突，或文件内两次出现内容冲突），整批拒绝，给出冲突行号与具体差异，**一条都不追加**；
- **未知选手、非法行、合并后超过 40 条 → 整批拒绝**：选手编号未登记、非正整数、门非法、秒数非非负整数、列数不对、空字段、表头不符、非 UTF-8、引号未闭合，以及合并后有效记录超过 40 条（重复条目不占位），都返回中文原因并保留原表。

### 顺序与会话状态

- **旧记录顺序不变**：确认只在记录表末尾追加（优先复用全空占位行），不改动、不重排任何旧行，也不改动选手与耗时区间；
- **新记录按文件首次出现顺序加入**；预览的新增清单即追加结果。
- 整批拒绝时**原表、人工复核与罚秒均保持原样**；成功追加后触发一次自动裁决——不相关趟的**复核与罚秒沿用原失效规则**保留/即时失效，旧的替代性诊断按原规则清除并在新结果上恢复入口。

### 预览失效与确认一致性（竞态规则）

- **预览期间仍可编辑**任何赛道输入；任何赛道输入（区间、选手、记录，含增删行、填入示例、清空）或**上传文件变化**（重新选择或清空选择）都会**立即使预览失效**：确认入口即刻消失；变化前发出的预览/确认请求无论何时返回（成功、422 或断网，“迟到响应”）都被版本守卫丢弃，**不能恢复确认入口**；
- **确认时输入仍须与预览一致**：确认请求会重新上传当前记录与同一文件，服务端独立重算；页面还会比对当前完整输入、文件身份（文件名/大小/修改时间）与服务端返回的新增/重复清单均与预览完全相同，任一不一致（含防抖期尚未触发重算的编辑）都拒绝追加并要求重新预览；
- 追加成功后文件选择自动清空，导入卡显示一次性“已追加 N 条（跳过 M 条重复）”提示；随后任何编辑或文件变化都会清除该提示。

## 比赛名次与罚秒（仅本次页面会话）

合法裁决结果顶部展示**比赛名次表**，列出每名选手的 **选手编号、计次数、原总用时、罚秒、调整后用时、名次**：

- **调整后用时 = 原总用时 + 罚秒**；
- 有完整计次的选手按 **计次数降序、调整后用时升序** 排名；两项都相同者**共享名次并跳号**（如 1、1、3），并列按编号升序展示；
- 计 0 次的选手排在末尾，按编号升序，**无名次**（显示“—”）。

名次表下方可为每名选手保存 **非负整数罚秒**（默认 0）与 **至多 200 字** 的原因；**罚秒大于 0 时原因必填**。校验失败时保存不生效，**保留原已保存的罚秒与原因**；保存成功后名次表**立即重排，无需重新裁决**。

- 罚秒**只影响名次表**：不改变采纳记录、计次数、裁决用时与人工复核，也不会发送到服务器；
- 罚秒仅保存在页面内存中，**刷新页面即全部清除**（不写入 localStorage 等任何持久存储）；
- 修改感应记录或耗时区间会**保留**已保存的罚秒；
- **任一选手行改号或删除时，在触发输入事件的当下立即清除该行原编号的罚秒与原因**——不必等待重算，也不论另一行是否仍占用同一编号（例如把 101 行临时改成 102 造成重号、再把原 102 行改为 104：原 102 行离开 102 的那一刻，102 的罚秒立即清除，不会因 101 行仍填着 102 而残留）；输入清空或非法（如重号）时同样立即清除。之后把编号**改回**、或删除后**重新添加同编号**，该编号也只显示默认 **0 秒、空原因**，旧罚秒不会随重算、过期响应或任何后续编辑恢复；未改号、未删除选手的处罚不受影响；
- “清空”与“填入示例”会同时清除全部罚秒；
- 输入非法或等待重算期间名次表隐藏；过期（已失效）的响应不会恢复名次表；最新合法结果总是套用当时已保存的罚秒。

## 人工复核（仅本次页面会话）

每趟已采纳计次下方都有“人工复核”区：可将该趟标记为 **未复核 / 通过 / 存疑**（默认未复核），并填写至多 **200 字**备注，点击“保存复核”生效。选择“存疑”时备注必须非空；备注超长或存疑无备注会保存失败，并**保留原已保存的复核内容**不变。

- 复核只是人工标注：**不改变**采纳方案、计次数与用时，也不会发送到服务器；
- 复核仅保存在页面内存中，**刷新页面即全部清除**（不写入 localStorage 等任何持久存储）；
- 复核按“选手编号 + 三条记录的 ID/门/秒数 + 该趟两段耗时 + 两段耗时区间”绑定到具体的趟，**不按趟序号或记录行号定位**；其中编号、秒数、两段耗时与区间都以规范十进制字符串精确比较（差值用 `BigInt` 精确计算），秒数超过 2^53、或两段差值小到 11 秒时也不会因浮点截断而误判。每次修改输入都会逐条核对已保存的复核，失效逐趟独立判定，一次编辑不会清空无关趟的复核：
  - **任一绑定值改变**（修改选手编号或两段耗时区间，或修改绑定记录的 ID、门、秒数），或**绑定记录、绑定选手被删除**，对应复核在输入变更的**当下立即丢弃**——不必等到返回合法裁决，即使当前输入非法、尚在防抖合并、或上一次请求仍在途也一样；之后再把值改回（例如下限清空触发非法报错后填回原值，或在防抖提交前改动后立即改回），该趟也只会显示**未复核、空备注**，旧状态与旧备注**不会恢复**；
  - 绑定值未变时（重排记录行、增删或修改无关记录、手动重新计算），只要该趟仍被最新合法裁决采纳，复核**原样保留**；最新合法裁决不再采纳的趟继续清除；过期响应（含非法响应）同样不能恢复已丢弃的复核；
- 输入非法或等待重算期间复核编辑区会隐藏；过期的响应不会覆盖正在编辑的新备注；
- “清空”与“填入示例”会同时清除全部复核记录。

## 替代性诊断（未采纳记录，只读分析）

合法裁决结果底部有一张独立的**“未采纳记录替代性诊断”**卡，点击 **🔎 检查替代性** 即可以**当前完整裁决输入**经 `POST /api/diagnose`（请求体与裁决完全相同）对每名选手的**未采纳记录**逐条诊断，并**按录入顺序**返回每条记录的 ID、门、秒数与分类：

- **同优可替代（`equal`）**：存在一条包含目标记录的**合法完整方案**，其**计次数与原总用时都与现方案相同**（现方案只是在 ID 决胜上赢出；同优判断不考虑 ID 决胜，也不考虑罚秒）。诊断结果同时给出该套**整套方案**按计次时间顺序串接的全部记录 ID 序列（每 3 条一趟）以及计次数、原总用时——不是只判断目标记录自己那一趟是否合格；同一目标存在多套同优方案时取 ID 序列字典序最小者。
- **仅次优可用（`inferior`）**：目标记录能出现在至少一条合格趟中（能成趟），但包含它的任何完整方案都无法同时达到现方案的计次数与原总用时（趟数更少，或趟数相同而原总用时更长）。
- **无法成趟（`unusable`）**：该选手的任何合格趟都不包含这条记录。

性质与边界：

- 诊断是**只读分析**：只在独立卡片展示，**不替换采纳结果**，也不改变计次数、人工复核、罚秒或名次；
- **输入一改或重新计算即清除**：修改任意输入（区间、选手、记录，含增删行与载入示例），或点击“⚖ 裁决 / 重新计算”手动重算（**即使输入未变**），诊断都立即消失，需在新结果上重新检查；
- **重算期间与裁决失败时不可检查**：每次裁决一开始（自动或手动）就清除旧诊断并禁止检查，**只有最新一次合法裁决完成后**才恢复“检查替代性”入口；裁决失败（输入非法或无法连接）时保持不可检查；诊断请求在途时按钮禁用；
- **重算前发出的诊断一律作废**：在重算开始前发出的诊断，无论何时结束——成功、服务报错或断网——都不会重新显示结果或错误，也不会改写重算后新诊断的在途、成功、失败状态；输入版本号与裁决序号双重守卫丢弃全部迟到响应；
- 诊断请求与裁决请求一样发送十进制字符串编号/秒数，任意大的编号与秒数全程无损，页面诊断卡也以规范十进制字符串精确展示；
- 诊断服务报错（如 422/无法连接）只在诊断卡内提示，可重试，不影响已展示的采纳结果与主错误框。

> 复现（修复前）：已有合法裁决与诊断结果时点击“裁决 / 重新计算”（输入未变），等待期间“检查替代性”仍可点击；若旧诊断 D1 仍在途，重算后新诊断 D2 已完成，D1 迟到的成功、服务错误或断网失败仍会覆盖 D2 的状态（手动重算不改变输入版本号，旧守卫放行了迟到响应）。修复后：每次裁决开始即递增裁决序号、清除旧诊断并禁止检查，只有最新合法裁决完成才恢复入口；重算前发出的诊断无论何时结束一律丢弃。未改输入的重算成功后，原人工复核与罚秒仍保留，名次按当前裁决恢复，诊断始终只读。

## 查找漏读（只补一条读数即可多完成一趟，只读提示）

诊断卡下方有一张独立的**“查找漏读”**卡，点击 **🧭 查找漏读** 即可以**当前完整裁决输入**经 `POST /api/missing`（请求体与裁决完全相同）推测：对每名选手枚举**任意两条不同门记录**与缺失门 S/M/F，若只补一条该门的虚拟读数（非负整数秒）即可与这两条记录成趟、并使该选手**最大计次数较原输入恰好增加 1**，则返回这两条记录的 ID 与缺失读数秒数的**闭区间**。

- **区间覆盖全部可行秒数**：闭区间 `[timeMin, timeMax]` 内的每个整数秒都满足——与该两条记录成趟（两段耗时均在区间内），且存在一套包含该新趟的合法完整方案（记录不共用、相邻趟严格分离）达到“原计次数 + 1”；区间外的秒数都不满足。**不能增次的记录对不返回**。
- **只比计次数**：判定不看各趟用时之和、ID 序列决胜与罚秒；新增一条读数最多让最大计次数 +1，故“增加 1”等价于“存在包含新趟的 K+1 趟合法方案”（K 为原最大计次数）。
- **不逐秒扫描**：含新趟 L 的最优方案规模 = A(L.起点−1) + 1 + B(L.终点+1)（A/B 为原记录上“终点 ≤ x / 起点 ≥ y”的最大趟数，由只比趟数的前缀/后缀 DP 求得）。A 随起点不减、B 随终点不增：缺 F 时条件化为 t ≤ 阈值、缺 S 时化为 t ≥ 阈值、缺 M 时与 t 无关，三种情形可行集都是闭区间，端点由二分直接算出——任意大的秒数（如超过 2^53）都按任意精度整数瞬时返回，区间再大也不会逐秒枚举。
- **排序**：响应按 选手编号数值升序 → 缺失门 S/M/F → 两条 ID（依门序）序列字典序 排列；**无解时页面明确提示**“当前输入下任何两条不同门记录都无法通过只补一条读数再多完成一趟”。
- **虚拟读数不占 40 条录入名额**：只是推测提示，不追加记录；记录已达 40 条上限时仍可正常查询。

性质与边界（与诊断同款）：

- 漏读是**只读提示**：只在独立卡片展示，**不追加记录**，也不改变裁决结果、人工复核、罚秒、名次与替代性诊断；
- **输入一改或重新计算即清除**：修改任意输入（区间、选手、记录，含增删行与载入示例），或点击“⚖ 裁决 / 重新计算”手动重算（**即使输入未变**），窗口都立即消失，需在新结果上重新查询；
- **重算期间与裁决失败时不可查询**：每次裁决一开始（自动或手动）就清除旧窗口并禁止查询，**只有最新一次合法裁决完成后**才恢复入口；裁决失败（输入非法或无法连接）时保持不可查询；查询在途时按钮禁用；
- **重算前发出的查询一律作废**：无论何时结束——成功、服务报错或断网——都不会重新显示结果或错误，也不会改写重算后新查询的在途、成功、失败状态（输入版本号与裁决序号双重守卫，迟到成功或失败均不回写）；
- 请求与裁决一样发送十进制字符串编号/秒数，任意大的编号与秒数全程无损，页面漏读卡也以规范十进制字符串精确展示区间端点；
- 服务报错（如 422/无法连接）只在漏读卡内提示，可重试，不影响已展示的采纳结果、诊断与主错误框。

## API

### `POST /api/adjudicate`（裁决）

```json
{
  "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
  "runners": [{"number": 101}, {"number": 102}],
  "records": [
    {"id": "a1", "runner": 101, "gate": "S", "time": 0},
    {"id": "b1", "runner": 101, "gate": "M", "time": 12},
    {"id": "c1", "runner": 101, "gate": "F", "time": 25}
  ]
}
```

- 合法：`200 {"ok": true, "result": {...}}`
- 非法输入：`422 {"ok": false, "error": "中文原因"}`（不返回部分结果）
- 请求体不是 JSON：`400`
- 编号字段（`runners[].number`、`records[].runner`）接受 JSON 整数或十进制字符串，**可为任意大的正整数**（如 `9007199254740993`）；响应中的 `runner` 以精确 JSON 数字原样返回，不截断、不缩小编号范围。前导零等值写法（如 `"007"`）按数值归一。
- 秒数字段（`standards.*`、`records[].time`）接受 JSON 整数或十进制字符串，**可为任意大的非负/正整数**（如 `9007199254741014`）；响应中的各 `time`、`smTime`、`mfTime`、`totalTime` 以精确 JSON 数字原样返回，字段、字段类型与状态码均不受影响。前端对这些值做十进制字符串无损处理，秒数再大也不会缩小取值范围或截断差值。
- 可选字段 **`excludedIds`**（隔离记录 ID 数组，缺省为空）：元素必须是**字符串**，按记录 ID 同款规则去首尾空白；不允许空白 ID、**重复 ID**（去空白后）或引用不存在的 ID，否则 `422`；显式 `null`/非数组同样 `422`。计算（含计次决胜规则）只使用**未隔离**记录，原始记录不删除；完整输入与 40 条限额先按原规则校验，隔离不能让非法输入变合法，也不影响设备日志合并。响应每名选手新增一列 `excluded`（按录入顺序的隔离记录 `{id, gate, time}`，与 `unused` 普通未采纳记录分列；不传 `excludedIds` 时为空数组）；某选手记录全部隔离时 `lapCount` 为 0。

# 隔离可疑起点 x2：它不再参与计算，结果中单列“excluded”
curl -s -X POST http://localhost:8000/api/adjudicate \
  -H 'Content-Type: application/json' \
  -d '{
    "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
    "runners": [{"number": 101}],
    "records": [

### `POST /api/diagnose`（替代性诊断）

请求体、输入校验、合法/非法/非 JSON 状态码（`200 / 422 / 400`）与编号、秒数字段规则都与 `POST /api/adjudicate` **完全相同**（同一套解析与校验，不改任何裁决行为），同样支持可选 `excludedIds`：诊断只针对**未隔离记录**计算方案，被隔离的记录既不被采纳、也不会出现在诊断结果中。响应只针对每名选手的**未采纳记录**，按录入顺序给出分类与同优替代方案：

```bash
curl -s -X POST http://localhost:8000/api/diagnose \
  -H 'Content-Type: application/json' \
  -d '{
    "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
    "runners": [{"number": 101}],
    "records": [
      {"id": "a1", "runner": 101, "gate": "S", "time": 0},
      {"id": "b1", "runner": 101, "gate": "M", "time": 12},
      {"id": "c1", "runner": 101, "gate": "F", "time": 25},
      {"id": "a2", "runner": 101, "gate": "S", "time": 30},
      {"id": "x2", "runner": 101, "gate": "S", "time": 30},
      {"id": "b2", "runner": 101, "gate": "M", "time": 45},
      {"id": "c2", "runner": 101, "gate": "F", "time": 57},
      {"id": "x1", "runner": 101, "gate": "M", "time": 200}
    ]
  }'
```

现方案两趟采纳 `a1,b1,c1` 与 `a2,b2,c2`（第二趟 `a2` 与 `x2` 同秒、同用时，ID 决胜选 `a2`），响应示例：

```json
{
  "ok": true,
  "result": {
    "runners": [
      {
        "runner": 101,
        "lapCount": 2,
        "totalTime": 52,
        "diagnoses": [
          {
            "id": "x2",
            "gate": "S",
            "time": 30,
            "classification": "equal",
            "alternative": {
              "lapCount": 2,
              "totalTime": 52,
              "recordIds": ["a1", "b1", "c1", "x2", "b2", "c2"]
            }
          },
          {"id": "x1", "gate": "M", "time": 200, "classification": "unusable"}
        ]
      }
    ]
  }
}
```

- `classification`：`equal` 同优可替代（附带 `alternative`：整套方案 `recordIds`、`lapCount`、`totalTime`）、`inferior` 仅次优可用、`unusable` 无法成趟；
- `diagnoses` 只包含未采纳记录，且顺序与请求中的记录录入顺序一致；
- 同优判定只比 `(lapCount, totalTime)`，不考虑 ID 决胜与罚秒；`alternative.recordIds` 是按计次时间顺序串接的**整套完整方案**（长度恰为 `3 × lapCount`，趟间严格分离、记录不共用）；
- 非法输入同样返回 `422 {"ok": false, "error": "中文原因"}`，请求体不是 JSON 返回 `400`。

### `POST /api/missing`（查找漏读）

请求体、输入校验、合法/非法/非 JSON 状态码（`200 / 422 / 400`）与编号、秒数字段规则都与 `POST /api/adjudicate` **完全相同**（同一套解析与校验，不改任何裁决行为），同样支持可选 `excludedIds`：前缀/后缀 DP 与窗口计算只基于未隔离记录，被隔离记录不参与任何候选趟。响应对每名选手给出“只补一条读数即可多完成一趟”的时间窗：

```bash
curl -s -X POST http://localhost:8000/api/missing \
  -H 'Content-Type: application/json' \
  -d '{
    "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
    "runners": [{"number": 102}, {"number": 7}],
    "records": [
      {"id": "sB", "runner": 102, "gate": "S", "time": 0},
      {"id": "fB", "runner": 102, "gate": "F", "time": 30},
      {"id": "sB2", "runner": 102, "gate": "S", "time": 100},
      {"id": "mB2", "runner": 102, "gate": "M", "time": 115},
      {"id": "mA", "runner": 7, "gate": "M", "time": 20},
      {"id": "fA", "runner": 7, "gate": "F", "time": 35}
    ]
  }'
```

响应示例（选手按编号数值升序；窗口按缺失门 S/M/F、两条 ID 序列字典序）：

```json
{
  "ok": true,
  "result": {
    "runners": [
      {
        "runner": 7,
        "lapCount": 0,
        "windows": [
          {"missingGate": "S", "ids": ["mA", "fA"], "timeMin": 0, "timeMax": 10}
        ]
      },
      {
        "runner": 102,
        "lapCount": 0,
        "windows": [
          {"missingGate": "M", "ids": ["sB", "fB"], "timeMin": 10, "timeMax": 20},
          {"missingGate": "F", "ids": ["sB2", "mB2"], "timeMin": 125, "timeMax": 175}
        ]
      }
    ]
  }
}
```

- 每个窗口：对 `ids` 这两条不同门记录（按门序 S→M→F 排列），补一条 `missingGate` 门的虚拟读数，秒数取闭区间 `[timeMin, timeMax]` 内任一整数，即可与这两条记录成趟、并使该选手最大计次数由 `lapCount` 增加 1；区间覆盖全部可行秒数，不能增次的记录对不出现；
- `timeMin` / `timeMax` 为非负整数（`timeMin ≤ timeMax`），以精确 JSON 数字返回，任意大的秒数不截断；判定只比计次数，不比用时、ID 决胜或罚秒；
- 端点是**只读**的：不追加记录（虚拟读数不占 40 条录入名额），不改变裁决、复核、罚秒、名次与诊断；
- 没有任何窗口时 `windows` 为空数组（页面会明确提示无解）；非法输入同样返回 `422 {"ok": false, "error": "中文原因"}`，请求体不是 JSON 返回 `400`。

### `POST /api/import/preview` / `POST /api/import/confirm`（设备日志合并预览/确认）

两个端点请求与响应合同完全相同（服务端不保存状态；确认由页面在追加前再次独立校验），请求为 `multipart/form-data`：

- `context`：当前选手与记录表的 JSON 字符串（形状同裁决请求的 `runners` 与 `records`，无需 `standards`，**也不携带 `excludedIds`**；沿用同一套校验，全空记录行作为占位行忽略）；合并始终对**完整原表**去重、计数与限额——页面上被隔离的记录同样占位、同样参与同 ID 冲突检测，隔离不能跳过冲突或绕过 40 条上限；
- `file`：设备导出的 UTF-8 CSV 文件，表头 `id,runner,gate,time`，支持 CSV 引号。

```bash
cat > /tmp/context.json <<'JSON'
{
  "runners": [{"number": 101}, {"number": 102}],
  "records": [
    {"id": "a1", "runner": "101", "gate": "S", "time": 0},
    {"id": "b1", "runner": "101", "gate": "M", "time": 12},
    {"id": "c1", "runner": "101", "gate": "F", "time": 25}
  ]
}
JSON

printf 'id,runner,gate,time\r\na1,101,S,0\r\n"d1","101","S","100"\r\ne1,102,M,200\r\n' > /tmp/log.csv

curl -s -X POST http://localhost:8000/api/import/preview \
  -F "context=</tmp/context.json;type=application/json" \
  -F "file=@/tmp/log.csv;type=text/csv"
```

`a1` 与现有记录内容一致 → 重复跳过；`d1`、`e1` 为新增：

```json
{
  "ok": true,
  "result": {
    "added": [
      {"id": "d1", "runner": 101, "gate": "S", "time": 100, "line": 3},
      {"id": "e1", "runner": 102, "gate": "M", "time": 200, "line": 4}
    ],
    "duplicates": [
      {"id": "a1", "runner": 101, "gate": "S", "time": 0, "line": 2}
    ],
    "existingCount": 3,
    "mergedCount": 5
  }
}
```

- `added` / `duplicates` 均按文件出现顺序排列，每项带 CSV 物理行号 `line`；`runner`、`time` 以精确 JSON 数字原样返回（任意大整数不截断），前导零等值写法按相同内容归入 `duplicates`；
- 同 ID 内容冲突、文件内同 ID 冲突、未知选手、非法行、合并后超过 40 条、CSV/编码/表头非法等任何情形：`422 {"ok": false, "error": "中文原因（含行号）"}`，**不返回任何部分新增**；缺少 `file` 返回 `400`，缺少或损坏 `context` 返回 `422`；
- 端点是**只读**的：服务端不保存任何状态，真正的追加发生在页面确认之后；页面确认前还会核对当前输入、文件身份与返回清单均与预览一致。

### `POST /api/bulletins/publish`（发布成绩公告）

请求体为点击时的完整快照：

```json
{
  "number": "2026-001",
  "baseVersion": 0,
  "input": {
    "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
    "runners": [{"number": 101}],
    "records": [
      {"id": "a1", "runner": 101, "gate": "S", "time": 0},
      {"id": "b1", "runner": 101, "gate": "M", "time": 12},
      {"id": "c1", "runner": 101, "gate": "F", "time": 25}
    ],
    "excludedIds": []
  },
  "reviews": [
    {
      "runner": "101",
      "records": [
        {"id": "a1", "gate": "S", "time": "0"},
        {"id": "b1", "gate": "M", "time": "12"},
        {"id": "c1", "gate": "F", "time": "25"}
      ],
      "status": "pass",
      "note": "确认无误"
    }
  ],
  "penalties": [{"runner": "101", "seconds": 3, "reason": "设备误触"}]
}
```

- `number`：**非空公告编号**（字符串，去首尾空白；JSON 整数按十进制文本接受），按原样文本保存，任意长的数字串都精确；
- `baseVersion`：**所见公告版本**（非负整数，首次发布为 0）；与当前最新版本一致才保存为下一版本，否则 `409`；
- `input`：完整裁决输入，形状与校验同 `POST /api/adjudicate`（含可选 `excludedIds`）；服务端**重新裁决**，不信任任何页面缓存结果；
- `reviews`：已保存复核（可缺省为空数组）：每条按 `runner` + 三条记录的 `id`/`gate`/`time` 匹配被采纳的趟；**每趟均须 `status: "pass"`**（零次选手无需复核），`note` 至多 200 字；不匹配、重复、未知选手或非“通过”都整次拒绝（`422`）；
- `penalties`：已保存罚秒（可缺省为空数组）：`seconds` 非负整数、`reason` 至多 200 字、罚秒大于 0 时原因必填；未知选手处罚或重复处罚整次拒绝（`422`）。

```bash
curl -s -X POST http://localhost:8000/api/bulletins/publish \
  -H 'Content-Type: application/json' \
  -d '{
    "number": "2026-001",
    "baseVersion": 0,
    "input": {
      "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
      "runners": [{"number": 101}],
      "records": [
        {"id": "a1", "runner": 101, "gate": "S", "time": 0},
        {"id": "b1", "runner": 101, "gate": "M", "time": 12},
        {"id": "c1", "runner": 101, "gate": "F", "time": 25}
      ]
    },
    "reviews": [
      {"runner": "101",
       "records": [{"id": "a1", "gate": "S", "time": 0},
                   {"id": "b1", "gate": "M", "time": 12},
                   {"id": "c1", "gate": "F", "time": 25}],
       "status": "pass", "note": "确认无误"}
    ],
    "penalties": [{"runner": "101", "seconds": 3, "reason": "设备误触"}]
  }'
```

成功：`200 {"ok": true, "result": {"number": "2026-001", "version": 1, "url": "/api/bulletins/2026-001?version=1"}}`；过期：`409 {"ok": false, "error": "…", "currentVersion": 1}`；校验失败：`422 {"ok": false, "error": "中文原因"}`；请求体不是 JSON：`400`。**任何失败都不留版本、也不改动现有公告。**

### `POST /api/bulletins/import`（导入公告归档，只追加缺失后缀）

请求体即导出得到的归档对象（上例响应中的 `result`）：

```bash
curl -s -X POST http://localhost:8001/api/bulletins/import \
  -H 'Content-Type: application/json' \
  -d @archive.json
```

- **格式校验（违反 → `422`，不写入任何编号）**：`format` 必须为 `1`；`bulletins` 为版本条目数组（可为空）；每条**恰好**含 `number`/`version`/`publishedAt`/`snapshot` 四个字段；**每个编号的版本必须从 1 起连续、无重复**；快照结构须与原读取结果一致（恰好 `input`/`adjudication`/`reviews`/`penalties`/`ranking` 五部分）。导入**不重新裁决**，快照原样搬运；
- **重叠版本须完全相同**：本地已存在的版本，其发布时间与快照须与归档一致——**对象键序忽略，数组顺序与 JSON 类型保留**（`1` 不等于 `"1"`、`true` 不等于 `1`，数组调序即不同）。相同项**跳过**，只**追加**本地缺失的后缀版本（发布时间按归档原样保存）；**本地链更长则全部跳过、本地保留**；
- **任一编号分叉 → `409 {"ok": false, "error": "公告 … 与本地已发布内容分叉，本次未导入任何编号"}`**，不写入任何编号；成功 `200 {"ok": true, "result": {"added": 新增版本数, "skipped": 跳过版本数}}`；请求体不是 JSON → `400`；
- **与既有发布按提交时库内状态协调**：重叠比对与追加在同一写事务中完成，无论与发布请求的提交顺序如何，都不会覆盖旧版、留下断链或写入半批；导入后原读取接口照常读最新与旧版，后续发布从最新版本继续；
- 编号、记录秒数与用时全程按任意精度整数/原样字符串处理，迁移不发生截断。
